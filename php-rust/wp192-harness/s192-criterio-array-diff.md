1. **Quesito**: con i simboli esatti delle librerie di sistema (profilo ORM `s192r1`) la voce «libsystem_platform» si scompone in `memmove` 5,6 % e `memcmp` 4,3 %; il builtin host `ho_array_diff` vale da solo **3,3 % INCLUSIVO** dei campioni dell'ORM (`s192-anatomia-inclusivo.py s192r1`: 1306 su 39.169) e compare fra i primi chiamanti di `memcmp` (0,4 %), `memmove` (0,2 %) e mimalloc. Lettura del codice: i valori degli array di confronto finiscono in un `Vec<Vec<u8>>` e ogni elemento del primo array fa `seen.contains(&s)`: O(n·m) confronti di stringhe.
2. **Forma**: `seen` diventa un `FxHashSet<Vec<u8>>` (`insert` al posto di `push`, `contains` invariato): O(n+m). Tre righe cambiate a saldo zero nel file host (al cap).
3. **Semantica**: identica per costruzione — stessa relazione (uguaglianza di byte della forma stringa), stesso ORDINE delle conversioni a stringa (prima tutti gli array di confronto, poi il primo: gli effetti di `__toString` restano dove sono), stesso ordine e stesse chiavi in uscita.
4. **Accettazione**: catena `s192-accettazione.sh` (build, catena S-190 con corpus-gate ×2, batteria).
