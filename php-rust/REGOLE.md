# REGOLE — processo phpr v1 lean (decisione utente 2026-08-07). Lista UNICA: cap 25 righe; una regola nuova entra solo sostituendone una. Niente sigle nuove.

1. **OBIETTIVO**: orizzonte parità (≥1×) col PHP oracle; tappa D (delibera utente S-186, 22/10): WP ≤1,5 · ORM ≤5 al netto del pavimento comune · micro ≤3× 6/6 (`wp97-harness/micro/`). Ogni sessione muove l'OGGETTO: ≥70% dei token sull'oggetto; apparato solo se blocca. **TIMEBOX**: apparato oltre ½ sessione = incidente ANCHE con parola dell'utente (deroga S-182 abrogata; S-180/182/183 contati — delibera S-186, firma 2026-10-23).
2. **COLLAUDO-NELL'ATTO**: ogni artefatto (pin, stash, golden) nasce SOLO dal suo script (`scripts/pin-phpr.sh`, `scripts/pin-server.sh`): build con ricetta + smoke + stash + registro in UN atto. Smoke fallito ⇒ niente stash. «Scoperto qualcosa di mai collaudato» = incidente di processo, si conta, non si celebra.
3. **MISURA**: criterio PRIMA (≤10 righe: segno, soglia = max(4 ns/iter, rumore, banda-layout), R, giudice); A/B interleaved ABAB, user CPU al netto dei pavimenti PER-binario; smoke R=2 con early-stop a segno opposto; N del giudice emesso dal sorgente; mai cifre da componenti o da contrasti tra binari diversi (solo direzione); guardie non-bersaglio a SOLO-REGRESSIONE; una guardia di misura si emenda solo rieseguendo il criterio emendato (rev. S-112); **misura di RECORD senza prova d'igiene (sentinelle) registrata nel suo `.out` = incidente, si conta** (decisione utente 2026-08-16, incidente 15); **arbitrato/derivato di guardia = COPIA DICHIARATA (copia-gate) verificata PRIMA del run; guardia su giudice quantizzato si ri-risolve a N con tick ≤ soglia/4 (backtrace ≥2,4M iter) sui bracci di record** (az.rev. S-154).
4. **ATTRIBUZIONE**: un Δ su una categoria non misurata in A/B proprio = «direzione+meccanismo firmati, magnitudine non ripartita». Voce fuori banda da >2 sessioni senza rerun blocca la leva successiva.
5. **GATE** (script, sempre, sul pin): batteria `cargo test --release` (rc dal comando, MAI da pipe) · corpus = fail-set CONGELATO per NOME ×2 modi (oggi 1407 — emende dichiarate 2026-10-22 §3.34/§3.35 e 2026-11-02 PR #4 enum; storia dei flip nei verdetti di promo) · fixture bilaterali (pin phpr E oracle) · micro R=5. Una lettera-gate che morde una leva promossa si emenda DICHIARANDO, col controllo ri-collocato dove il sito sopravvive. **GATE AUDITABILE** (S-186): fail-set ×2 e golden sono GATE, non output ⇒ IN GIT (`wp109-harness/corpus-gate/corpus-s109-{off,on}.fails`, `golden-content-{off,on}.tsv`); registro `.out` da solo = gate VOID; golden ri-basato SOLO con voce di catalogo PRIMA e verso dichiarato; gate invariante (`fxmc2`) = `diff(oracle,pin) == .expected-diff` committato, slittamenti ri-dichiarati.
6. **PIN**: build → hash → batteria → re-hash → stash → corpus/fixture → micro. Build dopo lo stash = gate nullo. Churn dichiarato; se include sorgente = «build emendata».
7. **REVISIONE**: UN revisore adversariale a fine sessione (≤400 parole, lente a rotazione misura→semantica→processo, mandato: trovare ciò che invalida il claim principale). Concilio a 9 sedie SOLO su richiesta utente, cambio di rotta, o audit ogni ~5 sessioni.
8. **REGISTRO** (sostituisce ROTAZIONE, delibera S-186, firma 2026-10-23): NEXT_SESSION ≤80 righe E ≤8.000 caratteri, riga ≤600 — giudice `scripts/next-budget.sh` in chiudi-sessione · riga 1 del NEXT = orizzonte + tappa + «delibera S-N, data» · un kill scattato entra in riga 1 nella STESSA sessione, per nome, e vi resta fino al concilio seguente (riscrittura che lo cancella = incidente) · cap `loc_dente` sale SOLO nel commit di promozione rc=0 con cifra nel `.out` · veti >3 sessioni in `gaps/VETI.md` · session file ≤40 · verdetti `.out` solo esiti e numeri · riga roadmap in MEMORY ≤3 righe · in testa a ogni report: frase semplice per non addetti + scoreboard (6 rapporti con frecce, riferimento WP, «leve spedite: N» — N=0 si dichiara).
9. **FEDELTÀ**: divergenze a catalogo per NOME, cercate PRIMA nel fail-set congelato; una cura cita i fail che deve flippare; byte-parity per ciò che sta in stringhe PHP, parità funzionale via crate per ciò che ne esce.
10. **OPERATIVE**: MySQL wp8 solo col datadir esterno (`mysql-wp8/data`) · uploads solo via guardia backup/wipe/restore · demoni via daemonizer con mkdir del log PRIMA e verifica pgrep · run pesanti sequenziali e detached, phpunit sotto watchdog · output di run mai nel repo (ECCEZIONE S-186: fail-set congelati e golden del corpus-gate sono GATE e stanno in git, §5) · `.rs` mai nei comandi git (`add -u` + `commit -F`) · Serena per il Rust, Vexp per il C · commit+push a ogni passo.
